# New Team Member Onboarding

**Difficulty:** Beginner  
**Estimated Time:** 2-3 hours  
**Prerequisites:** None

## Overview

Welcome to the Digital Technologies Research Group (DTRG)! This guide will help you get started as a new team member and familiarize yourself with our processes, tools, and resources.

## What You'll Learn

- How to access team resources and communication channels
- DTRG team structure and key contacts
- Development workflow and tools
- Documentation standards and where to find information

## Prerequisites

Before starting, you should have:
- [ ] Access to the team's GitHub organization
- [ ] Access to team communication channels (email, Slack, etc.)
- [ ] Your development machine ready

## Step 1: Getting Access

### GitHub Access
1. Ensure you're added to the UoA-DTRG GitHub organization
2. Review the repositories you have access to
3. Set up 2FA if not already enabled

### Communication Channels
1. Join the team communication platform (Slack/Teams/etc.)
2. Introduce yourself in the team channel
3. Subscribe to relevant project channels

## Step 2: Understanding Team Structure

### Key Roles
- **Team Leads**: [Names/Contacts]
- **Project Managers**: [Names/Contacts]
- **Technical Leads**: [Names/Contacts]

### Current Projects
Review the [Projects section](../projects/) to see active projects and determine which ones you'll be involved with.

## Step 3: Development Environment Setup

Follow the [Development Environment Setup Guide](dev-environment-setup.md) to configure your local development environment.

Key tools to install:
- Git
- Your project's programming language/runtime
- Code editor/IDE
- Docker (if needed for your projects)

## Step 4: Understanding Our Workflow

### Git Workflow
Read the [Git Workflow Guide](git-workflow.md) to understand:
- How we use branches
- Commit message conventions
- Pull request process

### Code Review
Familiarize yourself with the [Code Review Process](code-review-process.md):
- How to submit code for review
- What reviewers look for
- How to give good code reviews

## Step 5: Documentation

### Reading Documentation
- Browse this documentation repository to familiarize yourself with projects
- Check project-specific READMEs for setup instructions
- Use the search function to find specific information

### Writing Documentation
- Read the [CONTRIBUTING.md](../CONTRIBUTING.md) guide
- Use provided templates for consistency
- Ask questions if you're unsure how to document something

## Step 6: First Tasks

### Good First Issues
Look for issues labeled `good-first-issue` in project repositories to find suitable tasks for getting started.

### Pair Programming
Consider pairing with an experienced team member for your first few tasks to learn team practices.

## Verification

You're ready to start contributing when you can:
- [ ] Access all necessary team resources
- [ ] Navigate the team's GitHub organization
- [ ] Find and understand project documentation
- [ ] Set up your development environment
- [ ] Understand the basic workflow (Git, PR, code review)

## Next Steps

After completing this onboarding:
1. Review the [Projects documentation](../projects/) for projects you'll work on
2. Set up project-specific development environments
3. Attend the next team meeting
4. Schedule 1-on-1s with your project lead and relevant team members

## Questions or Issues?

If you encounter problems or have questions:
- Ask in the team chat channel
- Contact your team lead
- Reach out to experienced team members
- Open an issue in this docs repository for documentation improvements

## Welcome Aboard!

We're excited to have you on the team. Don't hesitate to ask questions - everyone is here to help!
